# Nebula Design System — agent instructions

Rules for agents (and humans) **editing this repository**. For *using* the
library in an app, see [`skills/nebula-ds/SKILL.md`](skills/nebula-ds/SKILL.md)
instead — do not copy maintainer rules into a consumer project.

## Non-negotiables

1. **Read [`docs/DESIGN_LANGUAGE.md`](docs/DESIGN_LANGUAGE.md) before
   creating, changing or reviewing any component, variant or class that
   ships.** It is the canonical visual authority.
2. **Never edit generated files.** `src/styles/tokens/primitives.css`,
   `src/styles/themes/light.css`, `src/styles/themes/dark.css` and
   `src/styles/tokens/manifest.json` are produced by
   `pnpm generate-themes` from the `nebula-ds-tokens` package. Change the
   tokens upstream, then regenerate.
3. **Variant names are frozen.** `filled | standard | outlined | text`,
   `size S | M | L`, and the `rounded` vocabulary
   (`Default, R, L, RTop, RBottom, LTop, LBottom`) stay as they are
   (owner decision, 2026-11-24). Their *semantics* are documented in the
   design language — extend documentation, never rename.
4. **Pin `@zag-js/*` at `1.43.0`.** `1.43.1` has a type-skew that breaks
   `useMachine` typing. Upgrade deliberately, never by caret.
5. **`restoreNativeFocus()` is load-bearing.** Storybook redefines
   `HTMLElement.prototype.focus` as an accessor and Zag.js reads it off the
   prototype (`Illegal invocation`). Keep the module-scope call in every
   Zag-backed component (`Menu`, `Sheet`, `Select`, `Dialog`, `Checkbox`,
   `RadioGroup`, `Toast`).
6. **Tokens only in CSS/JSX.** No literal colors, font sizes, spacings or
   radii in shipped code — `var(--nb-*)` everywhere. The lint of a new
   component should never need a disable comment for this.

## Repo conventions

- Component layout: `src/components/<name>/` with `<Name>.tsx`,
  `<Name>.css`, `__docs__/<Name>.stories.tsx`, `__test__/` (Vitest snapshots
  iterate the exported variant arrays). Variant maps live in
  `src/variants/<name>/` using `cva` and export the
  `<thing>Variants` lists that both stories and tests iterate.
- CSS is flat (no nesting), `nb-` prefixed, BEM-ish. Classes are plain
  names, never utilities; `clsxMerge` composes them.
- Every public prop has JSDoc — Storybook autodocs reads it into the
  Description column.
- Every story file sets `tags: ['autodocs', '!dev']` and a
  `parameters.docs.description.component` paragraph. Stories may use the
  demo-only classes from `src/styles/demo.css` (`nb-demo-*`, `nb-recipe-*`).
- A story must not accept `args` it ignores: use `render: (args) => …`, or
  set `control: false` for the prop.
- Known typos kept for history: `src/components/framePanel/__docs___`
  (three underscores).

## Verification

```bash
~/.local/bin/pnpm install
~/.local/bin/pnpm lint        # ESLint, --max-warnings 0 (also the pre-commit hook)
~/.local/bin/pnpm test        # Vitest, jsdom
~/.local/bin/pnpm build       # tsc + vite library build
~/.local/bin/pnpm build-storybook
```

`engines.node` is `>=24` (Vercel/CI use 24). A Node 22 host can still run
`lint`/`test`/`tsc`, but treat 24 as the contract.

## Docs ownership (keep the mirrors in sync)

| Surface | Owner |
| --- | --- |
| Visual authority | `docs/DESIGN_LANGUAGE.md`, `docs/PALETTE.md` |
| Consumer contract | `README.md` |
| Consumer skill | `skills/nebula-ds/**` (routes by task; grounded at a commit) |
| Full-page examples | `examples/<name>/` (each with README + dev-app route) |
| Machine index | `public/llms.txt`, generated by `pnpm generate-llms` |

After adding a component, example or doc, run
`~/.local/bin/pnpm generate-llms` and update the affected
`skills/nebula-ds/references/**` file in the same change. One rule, one
owner: link to the owning file instead of copying a rule.

## Gotchas that have bitten before

- `ThemeProvider` sets `data-nb-theme` on a wrapper `<div>`, **not** on
  `<html>`. When reading theme-scoped CSS vars via `getComputedStyle`, read
  from the themed wrapper element, not `document.documentElement`.
- `.storybook/preview.tsx` imports `../dist/style.css`, so Storybook needs
  `pnpm build` first — `pnpm storybook` does it for you; a bare
  `storybook dev` will fail on a clean checkout.
- Storybook's docs theme is light-only by design; the canvas follows the
  Theme toolbar toggle via `preview-head.html` overrides. Don't "fix" one
  without the other.
- Publishing happens **only** through the GitHub Publish workflows
  (`.github/workflows/publish.yml` → `release.yml`); never `npm publish`
  locally. Version bumps via `pnpm release <type>` without `--publish`
  (it also pushes the `vX.Y.Z` tag). The **GitHub Release** is created by
  `release.yml` from that tag (`--verify-tag` fails the job if the tag is
  missing — never publish a version that has no release entry again).
